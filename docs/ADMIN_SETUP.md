# 紹介者・案件管理

相談サイトは既存のまま維持し、同じリポジトリ・同じVercelプロジェクトの `/admin/` に管理画面を追加。
相談者のフォーム入力やLINEボタンのクリックでは案件を自動登録しません。LINE・メールで相談が届いた後、運営者が登録します。

## 実装済み

- 紹介者：管理用名、固定コード、活動中・停止。紹介者本人のログイン機能はありません。
- 紹介リンク：総合・転職・賃貸・インフラの案内先、紹介者コード `ref`、経路 `channel`、任意の流入元 `utm_source` を分離。
- 相談ページ間の移動で3項目を引き継ぎます。Cookie・localStorage・sessionStorageには保存しません。
- 直接LINE相談：紹介情報がある場合だけ、紹介コード等をコピーする案内を表示。LINEに自動送信しません。情報なしの直接相談は、受付時に紹介者・見た投稿を確認します。
- 案件：受付、同意待ち、同意取得、有効紹介、成約、報酬確定、入金、見送り。日付・共有先・同意した共有項目・税別紹介報酬を記録。
- 同意取得日・共有先・共有項目がない案件は、有効紹介として保存できません。
- 相談IDの重複拒否、日付順序検証、古い画面からの上書き拒否、CSV書き出し、操作履歴、案件削除。
- 紹介者別・経路別の受付、有効紹介、成約、確定報酬・入金済報酬を集計。受付月フィルターは案件の受付月で絞ります。入金月別の会計集計ではありません。

## 接続前の状態

VercelにDB・管理者設定がない場合、管理画面は設定待ちを表示して入力を無効化。APIは503を返し、実データを読み書きしません。サンプル案件で代用しません。
保存先の接続に失敗した場合も、保存できたという表示を返しません。

### 現在の接続設定（2026-10-13）

- Vercel `liberal-life` のPreviewに `DATABASE_URL`・`ADMIN_ACCOUNTS`・`ADMIN_SECRET` をSensitiveで設定。Productionへの設定・公開は行っていません。
- NeonのVercel管理プロジェクト `royal-firefly-14683705` 内に、専用ブランチ `aiplun-life-management-preview`（`br-falling-mouse-axit7lz6`）を作成。
- 専用DB `aiplun_life`、所有ロール `life_owner` に管理用の5テーブルを作成。アプリ接続は `life_app` ロールに限定し、管理テーブルの読み書き・シーケンス利用だけを許可。DB・ロール・テーブルの作成権限は付与しません。本番ブランチ・既存アプリのDBには書き込みません。
- Neonの新規プロジェクト作成はVercel管理組織の制約で拒否されたため、上記の分離ブランチを使用。ブランチの初期作成時には親のDBが複製されますが、管理アプリの接続先は新しい専用DBだけです。
- リージョンは既存NeonプロジェクトのOhio。Computeは最小・最大0.25 CU、自動停止。プラン変更は行っていません。既存プロジェクトと使用量枠を共有します。
- 管理者の初期ログイン情報は本人用ファイルで案内。接続URL・パスワード・共有リンクの秘密値はこの資料に記載しません。
- 今後のスキーマ変更は所有ロール `life_owner` の接続で実行します。Vercelのアプリ用 `DATABASE_URL` は `life_app` のまま維持してください。

以下は再構築・追加環境を用意する場合の手順です。現在のDBや管理者設定を重複して作成しないでください。

## Vercelでの初回設定

1. Vercelの `liberal-life` プロジェクト → Storage → Create Database → Neonを接続。対象はこのプロジェクトだけ。AIPLUN Studioには接続しません。料金・プランを確認して選択してください。
2. Preview専用のDBまたはNeonブランチを用意し、接続URLを `DATABASE_URL` としてPreview環境へ設定。既存の別アプリのDBを使わないでください。
3. リポジトリで `npm ci` 後、`node scripts/setup-admin.cjs` を実行。管理者名と16文字以上のパスワードを入力します。画面にパスワードは表示しません。
4. 作成された `.env.admin.local` の `ADMIN_ACCOUNTS` と `ADMIN_SECRET` をVercelのPreview環境変数へ登録。`ADMIN_ACCOUNTS` は外側のenv用引用符を除いたJSON配列を登録します。両方ともEncrypted/Sensitiveを使用。元パスワードは設定・保存しません。
5. ローカルの `.env.admin.local` にPreviewの `DATABASE_URL` を設定し、`node --env-file=.env.admin.local scripts/migrate.cjs` を実行。新しい専用DBに管理用テーブルだけを作ります。
6. Previewを再デプロイし、`/admin/` で設定した管理者名・パスワードを使ってログイン。紹介者登録→案件受付→同意→有効紹介→成約→報酬→入金を再確認します。
7. 共同運営者も使用する場合は `scripts/admin-account.cjs` で別アカウントのハッシュを作り、JSON配列に追加して再デプロイ。二人の権限は同じ管理者権限です。紹介者には管理画面のログイン情報を渡しません。

`.env.admin.local`・DBの接続URL・管理者設定・共有URLの秘密パラメータをGitHub、相談文、共有資料に載せないでください。
DBのプロバイダーでバックアップ・復旧の設定を確認してください。CSVは一覧の書き出し用で、DBバックアップの代わりではありません。

## 認証と保存

- パスワードはscryptでハッシュ化。公開コードにデフォルトアカウント・パスワードはありません。
- 管理APIはすべて認証必須。Vercelの共有リンクを知っているだけでは案件を閲覧できません。
- セッションはランダムトークン、DBにはトークンのハッシュを保存。CookieはHttpOnly・Secure・SameSite=Strict、期限8時間。ログアウトでDBのセッションを削除。パスワード変更後は古いセッションを拒否します。
- 書き込みは同一Origin・JSON・CSRFトークンを確認。ログインはDB共有の試行回数制限付き。
- 案件には本名、LINE ID、電話、住所、履歴書、相談全文を登録しません。管理ラベル・相談IDでLINEの履歴と対応づけます。
- ログには担当者・操作・案件ID・進捗のみを残します。CSVの数式実行を防ぐため、危険な先頭文字を無効化します。
- 保管期間と本人からの削除依頼対応は、既存の個人情報方針を確定して運用してください。案件削除は管理画面から行えます。操作履歴には識別用の内部IDが残ります。

## 検証

`npm run test:admin`：実際のPostgres SQLエンジン（PGlite）で受付〜入金、認証・CSRF・重複・同意・競合・書き出し・ログアウト・保存の永続性を確認。
`tests/admin-browser.cjs`：同じSQLエンジンに対してブラウザから紹介者登録・リンク作成・案件更新・集計、紹介コードの引き継ぎ・コピー・スマホ表示を確認。
`tests/e2e.cjs`：既存の相談フォーム・コピー・メール・LINE URL検証と説明ページを確認。

ローカルSQLはテスト・開発だけに使用。Vercel上の一時ファイルやブラウザ内を本番保存先として使用しません。
実クラウドDB・実アカウントによる確認結果は [VERIFICATION.md](VERIFICATION.md) に記録します。

## お部屋探し受付（追加機能）

- `/room.html` で希望条件を整理し、確認画面で「サイトから相談を送信する」を押した場合だけ `/api/room` にPOSTし、`life_room_inquiries` へ保存します。LINEに送る方式も引き続き使用できますが、LINEだけで相談した内容は自動登録されません。
- 管理画面 `/admin/` →「お部屋探し受付」で、管理者ログイン後に氏名・連絡先・希望条件・対応状況を確認します。新規受付／対応中／提携先への案内済み／対応終了、個別削除、既存案件管理への転記を用意しました。
- この専用受付DBには個人情報が含まれます。外部送信や第三者提供は自動化していません。共有する際は、提供先・共有項目・目的を説明し、別途本人の明示的な同意を取得してください。
- 受付にはPreview環境の`DATABASE_URL`・`ADMIN_SECRET`が必要。`life_room_inquiries`・`life_room_limits`のテーブルは専用NeonプレビューDB（`aiplun_life`）へ2026-10-20に追加済みで、`life_app` の必要権限も付与済み。
- 受付側は同一Origin確認、明示同意、入力検証、サイズ制限、honeypot、送信元IPのHMACハッシュを使った毎時上限、全体上限を実装。迷惑投稿完全防止を保証するものではありません。
- `main` の一般公開用ビルドは依然`previewOnly: true`により禁止。まずプレビューを検証してください。
